Deliver an agent experience under your own brand

Your brand, end to end

Logo, palette, typography, even the "thinking" animation must be yours — and swappable per business unit or end customer.

Your apps, in the loop

Users want the agent to show them the answer inside the tools they already use, not just describe it.

Your controls

Credentials stay server-side, write actions need approval, every user sees only their own history, and SSO identity flows through.

Your timeline

A hand-built chat front end with streaming, tools, resume, charts and deploys is months of work. It doesn't have to be.

The approach: Cortex Agents do the reasoning and governed data access; the Cortex Agent SDK gives you a typed client; Cortex Code generates the application around it.

What makes it one-shot-able

Explicit file layout, "read the SDK types before coding", a Step 0 spike that de-risks the riskiest API, acceptance criteria the model verifies itself, and hard rules (no secrets client-side, no deploy without asking).

Re-target in minutes

Change company, data domain and apps in the seed. Branding, domain and scenarios change; SDK integration, tool loop, resumable runs and deploy paths carry over.

Full toolset

bash, file read/write/edit, grep, glob, web search, SQL and skills in a Snowflake-managed sandbox scoped to the thread.

Approval cards

Every state-changing action arrives as tool_use with permission.options; the app replies with permission_decision.

Downloads

"Build a CSV of failed orders this week and a chart by reason" → files written in the sandbox appear as download chips.

Know the rules: call with caller's rights (owner's rights drops code tools), the sandbox has no direct data access (data comes through SQL tools), and code_toolset_all cannot be combined with code_execution. Preview feature.

Studio mode: headless Cortex Code for documents and apps

How it works

A small runner container uses @snowflake/cortex-agent-sdk/code query() with resume: one Cortex Code session per conversation, in a per-user workspace. SDK messages stream to the same chat UI.

Approvals with canUseTool

Reads and read-only SQL are auto-approved; bash and file writes become approval cards; write SQL is denied. Bundled skills are attached per intent and shown as chips.

Production checklist

Secrets

No Snowflake credentials in the bundle. PAT as a mounted file locally; service OAuth token in SPCS / App Runtime, re-read per request.

Identity

One resolveUser(): Sf-Context-Current-User ingress header, trusted SSO header, or dev default. REQUIRE_AUTH returns 401.

Caller's rights

CALLERS_RIGHTS=true runs agent calls with each user's own grants; required for code tools.

Isolation

Runs, history and Studio workspaces are owner-scoped; other users get 404.

Resilience

Proxy-owned resumable runs: reload mid-answer reattaches; Stop cancels server-side; 15 s keepalives.

Version pinning

The SDK is in Preview: pin @snowflake/cortex-agent-sdk@0.0.1, read the shipped types, and re-run the spike on upgrade.
