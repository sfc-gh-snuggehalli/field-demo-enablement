Why Teams Need an AI Gateway

Sprawl of keys and endpoints

Every team wires its own provider keys into agents, notebooks and apps. Nobody can say which models are in use or who is calling them.

No visibility into agent behaviour

A single agent turn fans out into several model calls and tool calls. Without traces, slow or failing turns are guesswork.

Spend you can't attribute or cap

Token-based billing scales with verbose prompts and runaway outputs. Finance needs per-user and per-team attribution and hard limits.

Optimization without evidence

Prompt and model choices are made by intuition. Teams need a repeatable way to prove a cheaper config keeps answer quality.

Pattern: Inference goes through the gateway; data access goes through MCP. Both authenticate as the same Snowflake user, so every token and every tool call is governed by RBAC and lands in telemetry you own.

What is Cortex AI Gateway?

A governed inference endpoint that Snowflake provisions for you

Inference

OpenAI Chat Completions and Anthropic Messages APIs. Any client that can override its base URL works: SDKs, LangChain, coding agents.

Observability

One OpenTelemetry span per request in AGENT_TRACE_TABLE('SNOWFLAKE'): model, timing, tokens, status, and optionally the full prompt and response.

Cost management

Credits per request in AI_GATEWAY_USAGE_HISTORY, attributed to the calling user. Budgets and per-user quotas apply to the AI GATEWAY domain.

Access control

USAGE to send requests, MONITOR to read traces and usage. Model access still follows Cortex model RBAC.

Not the same as Cortex Inference: /api/v2/cortex accepts the same requests, but only traffic through /api/v2/aigateways/SNOWFLAKE gets the gateway's access control, traces and cost attribution.

One Endpoint, Two Standard APIs

/v1/chat/completions

OpenAI-compatible. All non-Claude models (OpenAI GPT-5 family and others your account can reach).

/v1/messages

Anthropic-compatible. Claude models only. Use a Bearer token, not the SDK's default x-api-key header.

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="openai-gpt-5.4",
    base_url="https://<account-host>/api/v2/aigateways/SNOWFLAKE/v1",
    api_key=PAT,                                   # programmatic access token
    max_completion_tokens=4096,                     # GPT-5 family: not max_tokens
    default_headers={"traceparent": traceparent},   # groups one agent turn
)
Gotchas seen in the lab: hostnames must use hyphens, not underscores; GPT-5 models reject max_tokens; Claude sent to /chat/completions returns 400.

Snowflake as the Tool Provider (MCP)

One governed tool: a Cortex Agent behind the MCP server

CREATE AGENT MARKETING_AGENT ...        # Analyst (generates + runs SQL) + Search

CREATE MCP SERVER MARKETING_MCP FROM SPECIFICATION $$
tools:
  - name: marketing_agent
    type: "CORTEX_AGENT_RUN"
    identifier: "CORTEX_GATEWAY_LAB.PUBLIC.MARKETING_AGENT"
$$;
No raw SQL tool: the client can't bypass the semantic view. Clients connect over streamable HTTP at /api/v2/databases/<db>/schemas/<schema>/mcp-servers/<name> with the same PAT, and tools execute under the caller's role.

Every Call is Traced

SELECT TRACE:"trace_id"::STRING                                   AS trace_id,
       RECORD:"name"::STRING                                       AS span_name,
       RECORD:"status":"code"::STRING                             AS status,
       DATEDIFF('millisecond', START_TIMESTAMP, TIMESTAMP)        AS duration_ms,
       RECORD_ATTRIBUTES:"gen_ai.usage.output_tokens"             AS output_tokens,
       RECORD_ATTRIBUTES:"gen_ai.input.messages"                  AS prompt   -- payload capture
FROM TABLE(AGENT_TRACE_TABLE('SNOWFLAKE'))
WHERE TIMESTAMP > DATEADD('hour', -1, CURRENT_TIMESTAMP());

From Telemetry to a Better Agent

The closed loop the Trace Analyzer app runs

1. Observe
Traces + usage by user, model, trace
→
2. Diagnose
Advisor: latency, errors, token bloat
→
3. Experiment
Replay eval set, baseline vs candidate
→
4. Compare
Quality, p50/p95, tokens, errors
→
5. Promote
Client config + gateway allowlist + quota

Evidence, not intuition

Every experiment call carries its own traceparent, so each result row in OPTIMIZATION_RESULTS links back to its gateway span.

Quality gate

An AI_COMPLETE judge scores each answer 0-1 against EVAL_PROMPTS.EXPECTED; a candidate is promoted only if it stays within 0.05 of baseline.

Typical wins

Cap max tokens, constrain verbosity in the system prompt, or move simple workloads to a smaller model in the same family.

Admin Controls

ALTER AI GATEWAY SNOWFLAKE FROM SPECIFICATION $$
schema_version: 1
models:
  - name: '*'                     # or an explicit allowlist
logging:
  enabled: true
  enable_client_telemetry: true
  capture_payload:
    request_response: true
$$;                              -- replaces the whole spec

GRANT USAGE   ON AI GATEWAY SNOWFLAKE TO ROLE app_team;      -- send requests
GRANT MONITOR ON AI GATEWAY SNOWFLAKE TO ROLE platform_ops;  -- read traces/usage

CREATE SNOWFLAKE.CORE.QUOTA gateway_quota();
CALL gateway_quota!ADD_SHARED_RESOURCE('AI GATEWAY');
CALL gateway_quota!SET_PER_USER_LIMIT(10, 'DAILY');
CALL gateway_quota!SET_BLOCK_ENFORCEMENT_ENABLED(TRUE, FALSE);
USAGE is granted to PUBLIC by default. Revoke it to restrict who can send traffic; revoking USAGE is also how a budget action can cut a team off.

When to Use What

AI Gateway

  • External agents, SDKs, coding agents
  • Need traces, attribution, quotas
  • Standard OpenAI / Anthropic clients

MCP server

  • Give any agent governed Snowflake tools
  • Analyst + Search behind one Cortex Agent tool
  • No raw SQL tool to bypass the semantic view

Cortex Agents

  • Snowflake-hosted orchestration
  • Snowflake Intelligence front end
  • Built-in agent monitoring

Next Steps

1. Turn on logging

Set logging.enabled and capture_payload in the gateway spec, and grant MONITOR to the team that owns observability.

2. Point one agent at the gateway

Swap the base URL of an existing OpenAI or Anthropic SDK client and send a traceparent header per turn.

3. Run the optimization loop

Pick the top Advisor finding, replay an eval set with a candidate config, and promote it only if quality holds.

4. Add guardrails

Pin the model allowlist, then add a per-user quota with block enforcement and a shared-resource budget per team.

Govern the path, observe every call, and let the telemetry tell you which prompt and model to ship.
