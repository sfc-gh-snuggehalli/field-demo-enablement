# Speaker Notes: Building a Governed Field Sales Agent in Snowflake

## Account Context Summary

Prepared for a large medical device manufacturer that runs on AWS, uses Glean for enterprise search and Microsoft 365 / Teams for collaboration.

Scenario: a field sales assistant for a global medical device manufacturer. A LangChain agent outside Snowflake reasons with GPT-5.4 through Cortex AI Gateway and calls a governed Cortex Agent over MCP. The agent answers over sales performance, account health and a field document library, including share-loss risk scored by an XGBoost model in the Snowflake Model Registry. CoCo Desktop reaches the same agent, plus Glean, through Gateway Tools. The platform team wants one governed path for models and tools, full traces for every turn, and evidence-based tuning of prompts and models, with the optimizer itself governed and costed. The lab builds the data, the agent and MCP server, the gateway and Tools configuration, and a Streamlit Trace Analyzer that closes the loop from telemetry to a promoted config.

## Slide 2: The Use Case: A Medical Device Field Sales Agent

**Talking Points:**
- The business goal first: one agent that answers quota, account health and product questions with certified numbers and cited documents, and stays on-label.
- The data: 300 accounts (academic medical centers, community hospitals, ambulatory surgery centers, specialty clinics) rolled up to IDNs and GPOs, 24 territories in 4 regions, about 2,200 implanting physicians, about 215k market procedures, about $760M net revenue across 16 product families in 5 therapy areas.
- Two semantic views and a search service: SALES_PERFORMANCE_SV for revenue, quota, contracts and consigned inventory; ACCOUNT_HEALTH_SV for procedure share, competitive events, complaints and share-loss risk; PRODUCT_KNOWLEDGE_SEARCH over 77 field documents.
- Share-loss scores come from a model trained on ML_ACCOUNT_FEATURES and written to SHARE_LOSS_PREDICTIONS, which ACCOUNT_HEALTH_SV joins.

**Presenter Notes:**
- The data, product names and competitors (Corvex Medical, Brightline Scientific, Novix Health) are synthetic and generated by `lab/setup.sql`. Fiscal year is October 2025 to September 2026.
- SHARE_LOSS_PREDICTIONS is seeded from the legacy rule (`LEGACY_SEED`) until the notebook's model replaces it.
- Product families by therapy area if asked: Cardiac Rhythm (Pulsar Pacemaker, Sentinel ICD, Lumen Leadless Pacemaker, Arc Insertable Cardiac Monitor), Structural Heart (Valvia TAVR System, Annulus Repair Ring), Neuromodulation (Axion SCS, Axion DBS, Fluent Sacral Neuromodulation), Diabetes (Glyde Insulin Pump, Glyde CGM Sensor, Glyde Infusion Set), Surgical (Torque Powered Stapler, Torque Stapler Reload, Fuse Energy Sealer, Halo Hernia Mesh).

## Slide 4: Semantic Views: The Business Layer for AI

**Talking Points:**
- Two semantic views: SALES_PERFORMANCE_SV (net revenue, units, ASP, discount, quota attainment, contracts and price tiers, consigned inventory) and ACCOUNT_HEALTH_SV (procedure share vs competitors, evaluations, trials, value analysis reviews, conversions and win-backs, complaints, physicians and KOLs, share-loss risk).

- The semantic view is the governance boundary for text-to-SQL: Analyst writes SQL only over what it exposes, and that SQL runs as the caller.

## Slide 5: ML in the Same Platform: Share-Loss Model to Agent Answer

**Talking Points:**
- The question the model answers: which accounts will see procedure share fall 8 or more points in H2, using only signals known on 2026-03-31 (H1 share and trend, competitor evaluations and trials, complaints, days to contract renewal, discount, KOLs, expiring consigned inventory).
- The field's rule of thumb (renewal + complaints + trials) flags about 186 of 300 accounts against a real loss rate of about 29%. In our validation run, the XGBoost model reached holdout ROC AUC 0.78 vs 0.67 for the legacy rule.
- The notebook logs it to the Model Registry as SHARE_LOSS_MODEL/V1, batch-scores every account with `mv.run()` into SHARE_LOSS_PREDICTIONS, and attaches a model monitor. The semantic view already joins the scores, so the agent answers from model output.

**Presenter Notes:**
- `log_model` arguments are abridged on the slide; the notebook also passes sample input, target platform, task type and metrics.
- The AUC figures are from one validation run on synthetic data. Present them as directional.

## Slide 6: Cortex Agents: Orchestration Over Governed Tools

**Talking Points:**
- `MEDTECH_SALES_AGENT` has four tools: `sales_performance_analyst`, `account_health_analyst`, `product_knowledge_search` and `data_to_chart`. Its orchestration instructions say which questions go to which tool.

## Slide 7: Beyond Answers: Agents That Take Action

**Talking Points:**
- Agents aren't limited to answers. An action is a stored procedure (or UDF) exposed as a tool, either on the agent as a `generic` custom tool or directly on the MCP server as a `GENERIC` tool with `config.type: procedure`.
- Field example: the agent finds consigned units within 90 days of expiry, proposes rotating them to a higher-usage account as the consignment policy requires, then calls `CREATE_INVENTORY_ROTATION_REQUEST` to queue it and notify the territory manager.
- Two kinds of action: write back inside Snowflake (queue rotations, flag win-back visits, open complaint follow-ups), and reach outside Snowflake (email through a notification integration and `SYSTEM$SEND_EMAIL`, or a CRM or ticketing system through an external access integration).
- Keep a human in the loop by writing rows as `PENDING_APPROVAL` and returning the request id so the agent can say what it did.

**Presenter Notes:**
- This proc is illustrative and isn't in `lab/setup.sql`. Say so if anyone asks to see it run.
- Governance is the same as for reads: the caller needs `USAGE` on the procedure, and access to the MCP server doesn't grant access to its tools. Validate and cap arguments inside the proc, because prompt injection can shape tool inputs.
- Recommend putting write tools on the agent rather than exposing `SYSTEM_EXECUTE_SQL` (which is read-only by default and bypasses the semantic views).
